# Начало автоматизированного тестирования 1С

## 1. Загрузить справочник API

Прочитать живую схему `execute_testmanager_client_code`. Найти в описании строку:

```text
Справочник API тестирования: <абсолютный путь>
```

Прочитать указанный `README`. Он описывает иерархию объектов тестирования, доступные расширения, правила выполнения через прокси и расположение подробных материалов.

Если строки или файла нет, сообщить пользователю: справочник V8:Pulsar недоступен. Не восстанавливать API по памяти.

## 2. Проверить сеансы и зафиксировать исходное состояние

1. Вызвать `list_enterprise_sessions`.
2. Выбрать точный TestClient по идентификатору процесса, информационной базе и порту.
3. Проверить TestManager. Если TestClient есть, а TestManager нет, учесть, что прокси может запуститься при первом вызове `execute_testmanager_client_code`.
4. Снять снимок окна выбранного TestClient через `capture_screenshot` и сохранить его в `%TEMP%\v8-pulsar\baseline-<timestamp>.png`.
5. Если нужно состояние форм, после выбора TestClient получить список форм и состояние активной формы специализированными инструментами из живой схемы.

Если TestClient отсутствует, предложить запустить нужную базу как TestClient. Не выбирать обычный пользовательский сеанс вместо него без явного согласования.

## 3. Проверить канал автоматизированного тестирования

Выполнить через `execute_testmanager_client_code` для порта выбранного TestClient:

```bsl
АктОкно = Соединение.ПолучитьАктивноеОкно();
Результат = Строка(ТипЗнч(АктОкно));
```

Ожидаемый результат: `ТестируемоеОкноКлиентскогоПриложения`.

BSL-фрагмент выполняется в клиентском контексте TestManager. Вызовы через `ТестируемоеПриложение` отправляют команды TestClient, но не переносят туда выполнение самого фрагмента.

## 4. Сообщить о готовности

Указать:

- загружен ли справочник;
- выбранные TestClient, порт и TestManager;
- путь к исходному снимку;
- результат проверочного вызова;
- точную причину остановки, если среда не готова.

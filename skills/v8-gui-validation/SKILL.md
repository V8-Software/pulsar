# Проверяемая автоматизация интерфейса

Провести пользовательский сценарий до конечного наблюдаемого результата. Для каждого шага зафиксировать точную цель, фактический способ действия и доказательство полученного состояния.

## Порядок работы

1. Записать весь сценарий до первого действия: шаги, ожидаемые окна и конечный результат.
2. Установить точную цель через V8:Pulsar: идентификатор процесса, исполняемый файл, роль сеанса, главное окно и видимые дополнительные окна.
3. Выбрать самый узкий канал действия:
   - специализированный инструмент TestClient для управляемой формы 1С;
   - UI Automation для чтения дерева и семантических действий;
   - Win32 для проверенного действия по точному дескриптору окна;
   - ввод через общий рабочий стол только тогда, когда сценарий требует настоящего поведения мыши или клавиатуры.
4. Перед каждым изменением снять или прочитать исходное состояние.
5. Выполнить ровно одно действие и заново прочитать зависимое состояние.
6. Сопоставить результат с ожидаемым эффектом. Продолжать только после однозначной проверки.
7. После последнего шага проверить состав окон, состояние процесса и конечный пользовательский результат.

## Работа с видимым рабочим столом

Перед сменой активного окна, вводом с клавиатуры, перемещением мыши, действием по экранным координатам или снимком всего рабочего стола:

1. Предупредить пользователя, что агент временно использует общий рабочий стол.
2. Получить явное разрешение или воспользоваться установленным в среде механизмом резервирования рабочего стола.
3. Проверить, что целевое окно и процесс не изменились после получения разрешения.
4. Освободить рабочий стол сразу после последнего действия, которому он нужен.

Не считать активное окно доказательством отсутствия перекрытия. Если V8:Pulsar возвращает диагностику перекрытия, проверить её отдельно и при необходимости получить снимок.

## Доказательство результата

- Запуск или закрытие подтвердить новым списком сеансов.
- Действие TestClient подтвердить новым состоянием формы или значением элемента.
- Действие UI Automation подтвердить новым деревом, состоянием окна, снимком или визуальной разницей.
- Проверку фокуса подтвердить точным дескриптором активного окна до и после критического действия.
- Длительное или асинхронное изменение проверить отдельным наблюдением после ожидаемого времени выполнения.

Успешная доставка команды не доказывает пользовательский эффект. Если результат обозначен как доставленный, но не подтверждённый, не повторять действие автоматически: повторный клик или ввод может выполнить операцию дважды.

## Обработка ошибок

1. Прочитать структурный код ошибки и предлагаемое действие.
2. Не повторять тот же вызов с теми же параметрами при неизменном состоянии.
3. Обновить список сеансов, состояние формы или дерево окна перед следующим зависимым действием.
4. Если штатный инструмент V8:Pulsar должен работать, но возвращает противоречивый результат, остановить этот сценарий и сообщить пользователю о сбое инструмента.
5. Перед закрытием или завершением процесса повторно подтвердить его принадлежность текущей задаче.

## Итоговый отчёт

Указать:

- проверенный исполняемый файл, идентификатор процесса и главное окно;
- выполненный маршрут и результат каждого шага;
- фактический канал каждого действия;
- снимки, разницы или другие доказательства;
- конечные окна и состояние процесса;
- точную причину незавершённого шага, если сценарий остановлен.

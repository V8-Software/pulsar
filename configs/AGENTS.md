# Работа с 1С через V8:Pulsar

V8:Pulsar предоставляет MCP-инструменты для наблюдения за сеансами 1С, запуска 1С, работы с формами, окнами, снимками, отладчиком и справкой платформы.

При недоступности инструментов V8:Pulsar сообщи пользователю и останови зависящий от них сценарий.

## Роли сеансов

- **TestClient** — сеанс 1С:Предприятия, запущенный с поддержкой автоматизированного тестирования. Специализированные инструменты TestClient читают и изменяют его формы.
- **TestManager** — отдельный служебный сеанс-посредник, который управляет TestClient. BSL-фрагмент из `execute_testmanager_client_code` выполняется в TestManager, а вызовы через объект `ТестируемоеПриложение` отправляют команды для TestClient.
- **Конфигуратор** — его окна доступны через UI Automation, Win32 и инструменты отладчика.
- **Обычный сеанс 1С:Предприятия** — подходит для наблюдения. Для управляемой проверки форм запускай ту же базу как TestClient через `launch_1c_session` с `testClientPort`.

## Когда подключать навыки

- `testing-start` — перед автоматизированным тестированием форм 1С. Навык загружает справочник API, проверяет TestClient и TestManager и фиксирует исходное состояние.
- `v8-gui-validation` — для многошагового сценария в интерфейсе 1С или Windows, особенно когда нужны UI Automation, снимки, видимый рабочий стол или доказательство конечного результата.

## Карта инструментов

| Задача | Первый выбор | Следующий шаг и границы |
|---|---|---|
| Найти сеанс 1С, относящийся к текущей задаче | `list_sessions`; для узкой выборки — `list_enterprise_sessions` или `list_configurator_sessions` | Сопоставь идентификатор процесса, путь запуска, информационную базу и роль. Заголовок окна используй как дополнительный признак. `get_session` показывает подробности процесса, `get_launch_parameters` — параметры запуска. |
| Узнать окна и получить изображение | `list_windows` → `capture_screenshot` | Для фрагмента используй `crop_screenshot` с `cropCaptureRect` из сведений об окне или снимке одного `hwnd`. При `window_minimized` или `target_window_minimized` сначала подтверди принадлежность окна текущей задаче, затем при необходимости вызови `restore_window`. |
| Прочитать или изменить окно через UI Automation | Чтение — `get_form_elements`; действия — `click_uia_element`, `set_uia_element`, `send_keys`; переход по `e1cib` — `open_uia_navigation_link` | Сначала получи дерево целевого окна. После изменения обнови дерево перед следующим зависимым действием. |
| Начать автоматизированное тестирование форм | Навык `testing-start` | Он находит справочник API, проверяет TestClient и TestManager, снимает исходное состояние и выполняет проверочный вызов. При отсутствии навыка или справочника сообщи пользователю. |
| Выполнить BSL-код в управляемом сеансе | `execute_session_client_code` или `execute_session_server_code` | Для TestManager используй `execute_testmanager_client_code` или `execute_testmanager_server_code`. Если есть готовые инструмент, используй его в приоритете перед произвольным BSL-кодом. BSL-код может продолжать выполняться после тайм-аута ответа. |
| Запустить 1С | `launch_1c_session` | Для управления формами укажи `testClientPort`. После запуска вызови `list_sessions` или `get_session` и подтверди роль и идентификатор процесса. |
| Загрузить XML-исходники или собрать внешнюю обработку | `build_1c_config` — конфигурация или расширение; `build_epf` — внешняя обработка | Перед вызовом проверь информационную базу, исходники, выходной путь и версию платформы. |
| Проверить API платформы 1С | Точное имя — `get_platform_doc`; поиск по смыслу — `search_platform_docs` → `get_platform_doc` | Пустой результат по ожидаемому элементу считай возможным сбоем индекса и сообщи об этом пользователю. |
| Прочитать значение в остановленном отладчике Конфигуратора | `configurator_debug_health` → `capture_debug_value` | Продолжай при `status=ready`. Выбирай Конфигуратор по идентификатору процесса. Результат сохраняется в файл. |
| Изучить форму из XML без запуска 1С | `form_read_tree` → `form_read_item` | Сначала получи дерево и точный путь элемента. Эти инструменты работают в режиме чтения. |
| Прочитать оповещения приложения | `list_sessions` показывает ожидающие оповещения → `read_session_notifications` | Возвращает тексты оповещений, структурирует ошибки применения расширений и сохраняет их для следующих вызовов `list_sessions`. |
| Сохранить публикацию Infostart в Markdown | `convert_infostart_article` | Инструмент сохраняет текст, комментарии на всех страницах, изображения и вложения комментариев. Файлы самой публикации при наличии, например `.epf`, остаются за пределами результата. |
| Снять состояние явно зависшего процесса | `capture_unresponsive_process_screenshot` | Используй этот путь для зависшего процесса и с учётом доступа к видимому рабочему столу. Для обычного снимка выбирай `capture_screenshot`. |
| Завершить сеанс 1С | `close_session` | Сначала подтверди идентификатор процесса и принадлежность сеанса текущей задаче. `kill_session` применяй как явно согласованную крайнюю меру. Для файловой базы используй только `close_session`. |

## Порядок действий

1. **Выбрать сеанс 1С.** Получить актуальный список сеансов и сопоставить процесс, информационную базу и роль с текущей задачей.
2. **Выбрать канал.** Для формы TestClient использовать `testing-start`; для Конфигуратора — UI Automation или Win32; для остальных задач — самый узкий инструмент из карты.
3. **Выполнить одно действие.** Необратимые шаги выполнять по одному.
4. **Обновить наблюдение.** После запуска, перехода, открытия или закрытия формы заново получить список сеансов, состояние формы, дерево окна или снимок.
5. **Проверить пользовательский эффект.** Запуск и закрытие подтверждать составом сеансов; действие TestClient — состоянием формы; действие UI Automation — новым деревом, снимком или визуальной разницей.
6. **Обработать ошибку.** Прочитать структурный код и `suggestedAction`. Повторять вызов после изменения аргументов, выполнения предложенного действия или подтверждённого изменения состояния.

Ответ `delivered_unverified` подтверждает доставку команды, но оставляет пользовательский эффект неизвестным. Сначала обнови состояние; повтор допустим после исключения риска двойного клика, ввода или запуска.

## Безопасность

- Перед закрытием, завершением процесса, перезапуском, загрузкой конфигурации или изменяющим BSL-кодом заново подтверди идентификатор процесса, информационную базу и принадлежность текущей задаче.
- Закрывай и перезапускай только сеансы, созданные или явно выбранные для текущей задачи.
- Перед вводом с клавиатуры, перемещением мыши, сменой активного окна, действием по экранным координатам или снимком всего рабочего стола предупреди пользователя: эти операции используют общий видимый рабочий стол.
- Для проверки перекрытия окна используй диагностику окон и снимок; состояние активного окна служит только одним из признаков.
- Оценивай отдельно изменения информационной базы, файлов и состояния интерфейса.
- При отсутствии штатного инструмента или противоречивом результате останови зависящий сценарий и сообщи пользователю. Более широкий обходной путь используй после явного согласования.
- После тестирования возвращай Z-порядок windows окон и свернутость в исходное состояние. Закрывай открытые тобой диалоги, меню, восстанавливай исходное положение курсора, если ты его менял.

# Работа с 1С через V8:Pulsar

Используй MCP-инструменты V8:Pulsar для наблюдения за сеансами 1С, запуска 1С, работы с формами, окнами, снимками, отладчиком и справкой платформы. Этот файл не описывает внутреннее устройство Пульсара: для работы достаточно живых схем инструментов и правил выбора ниже.

Если инструменты V8:Pulsar недоступны, сообщи пользователю и останови зависящий от них сценарий. Не подменяй их произвольными командами, автоматизацией интерфейса или BSL-кодом без явной необходимости.

## Начало работы

1. Перед первым вызовом прочитай живую схему выбранного инструмента. Не угадывай имена и типы параметров: неизвестные аргументы отклоняются.
2. Начни с `list_sessions` и определи точную цель по идентификатору процесса, пути запуска, информационной базе и роли сеанса. Не выбирай цель только по заголовку окна.
3. Автоматизированное тестирование форм начинай с навыка `testing-start`: он загружает справочник API тестирования и проверяет готовность TestClient и TestManager. Для Конфигуратора и сценариев без подходящего API TestClient используй UI Automation или Win32.
4. Выбирай самый узкий специализированный инструмент, который даёт нужный результат. Произвольный BSL-код — запасной путь, а не замена готовой операции.
5. После любого изменения заново прочитай состояние, от которого зависит следующий шаг.

## Когда подключать навыки

- `testing-start` — в начале автоматизированного тестирования форм 1С. Навык загружает справочник API, проверяет TestClient и TestManager и фиксирует исходное состояние.
- `v8-gui-validation` — для многошагового сценария в интерфейсе 1С или Windows, особенно когда нужны UI Automation, снимки, видимый рабочий стол или доказательство конечного результата.

Навык задаёт порядок работы, а живая схема MCP-инструмента — допустимые параметры конкретного вызова. Не дублируй подробности навыков в этом файле.

## Роли сеансов

- **TestClient** — сеанс 1С:Предприятия, запущенный с поддержкой автоматизированного тестирования. Его формы читают и изменяют специализированные инструменты, которые выбираются по навыку `testing-start` и загруженному им справочнику.
- **TestManager** — отдельный служебный сеанс, который управляет TestClient. BSL-код из `execute_testmanager_client_code` выполняется в контексте TestManager; вызовы через объект `ТестируемоеПриложение` отправляют команды TestClient, но не переносят туда выполнение самого фрагмента.
- **Конфигуратор** — для его окон используй инструменты UI Automation, Win32 и отладчика.
- **Обычный сеанс 1С:Предприятия** — подходит для наблюдения и доступных операций. Для сеанса, которым агент управляет в текущей задаче, TestClient — основное состояние, а запуск без `/TestClient` — случайное. После подтверждения точного процесса такой сеанс можно закрыть и заново открыть для той же базы через `launch_1c_session` с `testClientPort`.

## Карта инструментов

Карта помогает выбрать первый инструмент, но не заменяет его живую схему. Если схема расходится с этой картой, не угадывай: останови сценарий и сообщи пользователю о расхождении.

| Задача | Первый выбор | Что учесть |
|---|---|---|
| Найти сеанс и определить его роль | `list_sessions`; для узкой выборки — `list_enterprise_sessions` или `list_configurator_sessions` | `get_session` показывает подробности одного процесса, `get_launch_parameters` — параметры его запуска. |
| Узнать окна и получить изображение | `list_windows` → `capture_screenshot` | Для фрагмента используй `crop_screenshot` с `cropCaptureRect`, полученным от `list_windows` или снимка одного `hwnd`. При `window_minimized` или `target_window_minimized` сначала проверь принадлежность окна текущей задаче; если восстановление входит в сценарий, используй `restore_window`. |
| Прочитать или изменить обычное окно через UI Automation | Чтение — `get_form_elements`; действия — `click_uia_element`, `set_uia_element`, `send_keys` | Сначала получи дерево целевого окна. После изменения получи его заново. Для перехода по `e1cib` используй `open_uia_navigation_link`. |
| Начать автоматизированное тестирование форм | Навык `testing-start` | Он находит справочник API, проверяет TestClient и TestManager, снимает исходное состояние и выполняет проверочный вызов. Конкретные инструменты TestClient выбирай по навыку и живым схемам, а не по памяти. Если навык не установлен или справочник недоступен, сообщи пользователю. |
| Выполнить BSL-код в управляемом сеансе | `execute_session_client_code` или `execute_session_server_code` | Для TestManager используй только `execute_testmanager_client_code` или `execute_testmanager_server_code`. Тайм-аут ответа не отменяет уже запущенный BSL-код. |
| Запустить 1С | `launch_1c_session` | Для управления формами укажи `testClientPort`. После запуска заново вызови `list_sessions` или `get_session` и подтверди роль и идентификатор процесса. Не подменяй инструмент ручной командой, пока его контракт покрывает задачу. |
| Загрузить XML-исходники или собрать внешнюю обработку | `build_1c_config` — конфигурация или расширение; `build_epf` — внешняя обработка | Это разные операции. До вызова проверь информационную базу, исходники, выходной путь и версию платформы. |
| Проверить API платформы 1С | Точное имя — `get_platform_doc`; поиск по смыслу — `search_platform_docs` → `get_platform_doc` | Если ожидаемый элемент не найден, сообщи о возможном сбое индекса. Не делай вывод об отсутствии API только по пустому поиску. |
| Прочитать значение в остановленном отладчике Конфигуратора | `configurator_debug_health` → `capture_debug_value` | Продолжай только при `status=ready`. Выбирай Конфигуратор по идентификатору процесса. Результат сохраняется в файл. |
| Изучить форму из XML без запуска 1С | `form_read_tree` → `form_read_item` | Сначала получи дерево и точный путь элемента. Эти инструменты не редактируют форму. |
| Прочитать оповещения приложения | `list_sessions` показывает ожидающие оповещения → `read_session_notifications` | Чтение может пометить или удалить оповещения. Не считай его полностью пассивной диагностикой. |
| Сохранить публикацию Infostart в Markdown | `convert_infostart_article` | Инструмент сохраняет текст, комментарии, изображения и вложения комментариев, но не скачивает файлы самой публикации, например `.epf` или `.dt`. |
| Снять состояние явно зависшего процесса | `capture_unresponsive_process_screenshot` | Это отдельный путь с доступом к видимому рабочему столу. Не используй его вместо обычного `capture_screenshot`. |
| Завершить сеанс 1С | `close_session` | `kill_session` — только явно подтверждённая крайняя мера и никогда для файловой базы. Перед действием заново проверь процесс и его принадлежность текущей задаче. |

## Обязательный порядок действий

1. **Установить цель.** Получить актуальный список сеансов и подтвердить нужный процесс и его роль.
2. **Выбрать узкий инструмент.** Не заменять специализированную операцию произвольным BSL-кодом, ручным запуском или управлением интерфейсом.
3. **Прочитать контракт.** Использовать только параметры из живой схемы и учитывать заявленные побочные эффекты.
4. **Выполнить одно действие.** Не объединять несколько необратимых шагов в один вызов или сценарий.
5. **Обновить наблюдение.** После запуска, перехода, открытия или закрытия формы заново получить список сеансов, состояние формы, дерево окна или снимок.
6. **Проверить пользовательский эффект.** Запуск и закрытие подтверждать составом сеансов; действие TestClient — состоянием формы; действие UI Automation — новым деревом, снимком или визуальной разницей.
7. **Обработать ошибку.** Прочитать структурный код и `suggestedAction`. Не повторять тот же вызов с теми же параметрами при неизменном состоянии.

Успешная доставка команды не доказывает результат. Ответ `delivered_unverified` не повторяй автоматически: повторный клик, ввод или запуск может выполнить операцию дважды.

## Безопасность и границы

- Перед закрытием, завершением процесса, перезапуском, загрузкой конфигурации или изменяющим BSL-кодом заново проверь точную цель.
- Не закрывай и не перезапускай сеанс, если не доказано, что он создан или выбран для текущей задачи.
- Перед вводом с клавиатуры, перемещением мыши, сменой активного окна, действием по экранным координатам или снимком всего рабочего стола предупреди пользователя: эти операции используют общий видимый рабочий стол.
- Не считай активное окно доказательством того, что целевое окно не перекрыто. Используй диагностику окон и снимок.
- Инструмент может не менять информационную базу, но записывать файл или менять состояние интерфейса. Оценивай каждый побочный эффект отдельно.
- Если штатный инструмент отсутствует, возвращает противоречивый результат или работает не так, как описывает живая схема, останови зависящий от него сценарий и сообщи пользователю. Не переходи молча к более опасному обходному пути.

## Что не нужно искать

- Не ищи исходный код, внутренние спецификации или архитектуру V8:Pulsar: они не нужны для вызова MCP-инструментов.
- Не сохраняй в этом файле каталог инструментов TestClient, полные схемы параметров, длинные примеры ответов и детали реализации: они устаревают и расходуют постоянный контекст. Для TestClient используй навык `testing-start`, для остальных инструментов читай живую схему перед вызовом.
- Не вызывай все инструменты для знакомства с системой. Начинай с задачи пользователя и выбирай только нужную ветку карты.
- Не выводи из этого шаблона правила сборки, Git или оформления кода проекта пользователя. При объединении файлов сохрани собственные правила проекта рядом с этим разделом.

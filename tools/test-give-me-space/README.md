# test-give-me-space

`test-give-me-space.exe` — маленькая Windows-утилита для координации тестов, которым нужен живой рабочий стол пользователя.

Утилита показывает крохотную чёрную плашку поверх окон на каждом подключённом мониторе, предупреждает пользователя перед началом тестирования и возвращает агенту понятный статус. Все плашки относятся к одной общей сессии: клик по любой из них отменяет или останавливает ту же проверку. Положение запоминается отдельно для каждого логического монитора. После отключения, переподключения или перенумерации дисплеев Windows сохранённое положение может перейти на другой физический экран, но всегда ограничивается рабочей областью текущего экрана. Утилита не блокирует клавиатуру, не перехватывает `Space`, `Enter`, `Esc` и не вызывает `BlockInput`.

## Когда использовать

Используйте утилиту перед действиями, которые могут задеть активное окно пользователя:

- UIA-действия;
- физический ввод клавиш или мыши;
- сценарии, которые работают только с окном переднего плана;
- тестовые скрипты без фонового режима.

Не оборачивайте ею фоновые действия через TestClient, BSL, HTTP, файловый обмен и другие механизмы, которые не трогают пользовательский ввод.

## Команды

```powershell
test-give-me-space.exe request
test-give-me-space.exe request --purpose observe-windows
test-give-me-space.exe request --owner 019e02f6-8b5d-7431-bf62-77462c424b2a
test-give-me-space.exe request --purpose observe-windows --owner 019e02f6-8b5d-7431-bf62-77462c424b2a
test-give-me-space.exe status
test-give-me-space.exe finish --owner 019e02f6-8b5d-7431-bf62-77462c424b2a
test-give-me-space.exe cancel --owner 019e02f6-8b5d-7431-bf62-77462c424b2a
test-give-me-space.exe hide --owner 019e02f6-8b5d-7431-bf62-77462c424b2a
test-give-me-space.exe show --owner 019e02f6-8b5d-7431-bf62-77462c424b2a
test-give-me-space.exe avoid-point --x <screen-x> --y <screen-y> --owner 019e02f6-8b5d-7431-bf62-77462c424b2a
test-give-me-space.exe restore-position --owner 019e02f6-8b5d-7431-bf62-77462c424b2a
test-give-me-space.exe --help
test-give-me-space.exe --version
```

Флаги `--purpose` и `--owner` у `request` можно передавать в любом порядке. У `finish`, `cancel`, `hide`, `show`, `avoid-point` и `restore-position` поддерживается `--owner`. Если `--owner` не задан, утилита использует `TEST_GIVE_ME_SPACE_OWNER`, а затем `CODEX_THREAD_ID`, если такая переменная есть.

Запуск без аргументов, `--help`, `-h`, `help`, а также `request --help`, `status -h` и похожие варианты справки выводят краткую справку и завершаются с кодом `0`.

`--version` и `-V` выводят версию исполняемого файла и завершаются с кодом `0`.

`request` запускает серверный процесс, если он ещё не запущен, показывает плашку с отсчётом 10 секунд, подаёт звуковой сигнал и ждёт результата. Сервер запускается вне дерева короткой CLI-команды, поэтому оболочки, которые ждут дерево процессов, не должны удерживать `request` после результата. Общий бюджет ожидания для `request` — 30 секунд: в него входят старт сервера, готовность канала, отсчёт и чтение ответа. Если сервер не ответил за это время, команда возвращает `ipc_error` с кодом `50`.

Если пользователь не кликнул по плашке, команда возвращает:

```json
{"status":"granted"}
```

После этого плашка остаётся на экране с текстом `Идёт тестирование...`.

`request --purpose observe-windows` запускает тот же охраняемый участок, но с текстами для изучения текущего состояния окон. Этот режим нужен перед чтением волатильного состояния рабочего стола: активное окно, видимость, свёрнутость, развёрнутость, список окон и похожие проверки, где пользователь или другой агент может изменить состояние между замерами.

`--owner` помечает охраняемый участок идентификатором агента или чата. `status`, `busy_*`, `stopped_by_user` и `closed_by_user` возвращают этот идентификатор в JSON вместе с `startedAtUtc`, чтобы агент мог отличить свой участок от чужого или старого.
`finish` и `cancel` с другим `owner` не закрывают текущую плашку и возвращают `owner_mismatch`.
Запуск без `owner` считается ручным или совместимым со старым протоколом: его можно закрыть командой `finish` или `cancel` с любым владельцем, потому владельца для сравнения нет.

`avoid-point` временно перемещает только плашку, перекрывающую экранную точку `--x`, `--y`. Команда доступна только владельцу уже разрешённой сессии; другой или отсутствующий владелец получает `owner_mismatch`. Новая позиция остаётся в рабочей области того же монитора и не перекрывает указанную точку. Исходная позиция хранится только в памяти и не изменяет сохранённое пользователем положение. `restore-position` того же владельца возвращает временно перемещённую плашку; повторные вызовы обеих команд безопасны. При `finish`, `cancel` и ручном закрытии временная позиция восстанавливается и очищается.

`hide` и `show` доступны только владельцу уже разрешённой сессии. Они временно скрывают и затем возвращают все плашки этой сессии, не меняя состояние `running`, владельца, таймер или сохранённые положения. Помощник GUI использует их только вокруг одного глобального клика и всегда вызывает `show` в `finally`.

Пример:

```json
{"status":"running","owner":"019e02f6-8b5d-7431-bf62-77462c424b2a","startedAtUtc":"2026-05-20T00:46:18+00:00"}
```

`status` возвращает текущее состояние. Если сервер не запущен, команда быстро читает терминальное состояние из `%LOCALAPPDATA%\TestGiveMeSpace\state.json`; если терминального состояния нет, возвращает `idle`.

Если сервер уже начал штатно закрываться после `finish`, `status` коротко повторяет проверку канала. Когда сервер успел завершиться, команда возвращает `idle` или сохранённое терминальное состояние, а не технический сбой. Если мьютекс сервера остаётся, но канал продолжает не отвечать, это считается `ipc_error`.

`finish` штатно завершает тестирование и закрывает плашку. Звуковой сигнал закрытия подаётся только если после открытия плашки прошла хотя бы 1 минута. Для звукового сигнала используется системный звук Windows. После ответа `finished` команда до 2 секунд ждёт исчезновения серверного мьютекса, но не превращает задержку закрытия в ошибку: успешный ответ остаётся `finished`.

`cancel` сбрасывает состояние, закрывает плашку, если сервер запущен, и очищает терминальное состояние.

## Поведение пользователя

Во время отсчёта плашка показывает:

```text
Тест забирает управление, клик для отмены: 10
```

В режиме изучения состояния окон отсчёт показывает:

```text
Изучение состояния окон, клик для отмены: 10
```

Левый клик во время отсчёта отменяет старт и возвращает:

```json
{"status":"cancelled_by_user","message":"Тестирование отменено пользователем"}
```

Во время активного тестирования плашка показывает:

```text
Идёт тестирование...
```

В режиме изучения состояния окон:

```text
Изучение состояния окон
```

Первый левый клик меняет текст на:

```text
Остановить тестирование?
```

В режиме изучения состояния окон:

```text
Остановить изучение? Клик для остановки.
```

Повторный левый клик в течение 5 секунд останавливает тестирование, сохраняет терминальное состояние и закрывает плашку. Если второго клика нет, текст возвращается к `Идёт тестирование...`.

Правый клик открывает встроенное мини-меню с пунктом `Закрыть`. Это аварийный ручной сброс для случаев, когда агент упал или не вызвал `finish`.

Во время движения мыши плашка на короткое время меняет цвета: фон становится белым, текст чёрным. Это заметный сигнал, что пользователь снова трогает рабочий стол.

Если активная плашка не закрыта командой `finish`, `cancel` или пользователем, сервер сам закрывает её через 10 минут, сохраняет терминальное состояние и завершает процесс. Следующий `status` или `finish` вернёт:

```json
{"status":"closed_by_timeout","message":"Плашка закрыта по таймауту"}
```

## Коды выхода

| Код | Статус | Смысл |
|---:|---|---|
| 0 | `granted`, `running`, `finished`, `idle`, `cancelled` | Команда выполнена штатно |
| 20 | `cancelled_by_user` | Пользователь отменил старт во время отсчёта |
| 21 | `stopped_by_user` | Пользователь остановил уже начатое тестирование |
| 22 | `busy_countdown`, `busy_running`, `busy_confirm_stop`, `owner_mismatch` | Уже есть охраняемый участок или он принадлежит другому владельцу |
| 23 | `closed_by_user` | Пользователь закрыл плашку через меню |
| 24 | `closed_by_timeout` | Плашка закрылась сама через 10 минут |
| 50 | `ipc_error`, `server_not_ready` | Сервер не готов или не отвечает |
| 51 | `protocol_error` | Некорректная команда или ответ |
| 52 | `io_error` | Критичная ошибка чтения или записи состояния |

Служебные команды `request`, `status`, `finish` и `cancel` всегда пишут в stdout JSON минимум с полем `status`.
Человекочитаемые команды `--help`, `-h`, `help`, `--version` и `-V` пишут обычный текст в stdout.
Некорректные команды и параметры сохраняют JSON-ответ в stdout и дополнительно пишут понятное сообщение в stderr.
Поля `owner` и `startedAtUtc` являются локальной диагностической меткой, а не секретом.

## Пример для агента

```powershell
$exe = "C:\tools\test-give-me-space\test-give-me-space.exe"

& $exe request --owner $env:CODEX_THREAD_ID
if ($LASTEXITCODE -ne 0) {
    exit $LASTEXITCODE
}

try {
    # Действия теста, которым нужен живой рабочий стол.
    & $exe status
    if ($LASTEXITCODE -ne 0) {
        exit $LASTEXITCODE
    }
}
finally {
    & $exe finish --owner $env:CODEX_THREAD_ID
    if ($LASTEXITCODE -ne 0) {
        exit $LASTEXITCODE
    }
}
```

Для длинных сценариев вызывайте `status` между шагами или внутри цикла. Если `status` или `finish` вернул код `21`, `23` или `24`, сценарий должен остановиться и сообщить текст из поля `message`.

## Сборка и проверка

Для сборки требуется .NET SDK 9:

```powershell
dotnet test .\TestGiveMeSpace.Tests\TestGiveMeSpace.Tests.csproj -c Release
dotnet publish .\TestGiveMeSpace.App\TestGiveMeSpace.App.csproj -c Release
```

Скрипт `verify-publish.ps1` собирает поставку во временном каталоге и проверяет состав файлов и базовые команды:

```powershell
.\verify-publish.ps1
```

## Устройство

Серверный процесс использует именованный канал `TestGiveMeSpace.{SessionId}` и мьютекс `Local\TestGiveMeSpace.{SessionId}`. `SessionId` берётся из текущей Windows-сессии, поэтому утилита координирует именно текущий интерактивный рабочий стол.

Короткая CLI-команда `request` запускает внутренний `test-give-me-space-server.exe` через временный ярлык, открытый `explorer.exe`. Это нужно, чтобы долгоживущий WPF-сервер не оставался потомком процесса `request` для оболочек, которые ждут всё дерево процессов. CLI остаётся консольной программой для JSON-ответов агенту, а server-exe собран как WPF `WinExe`, поэтому пользователь видит только плашку без отдельного консольного окна.

`test-give-me-space-server.exe` — внутренний файл поставки. Агенты вызывают только `test-give-me-space.exe`.

Проверка `verify-publish.ps1` публикует CLI во временную папку и требует,
чтобы в поставке рядом лежали `test-give-me-space.exe`, `test-give-me-space-server.exe`
и не было лишних файлов вида `test-give-me-space-server.*`.
Перед публикацией скрипт удаляет старые временные папки `test-give-me-space-publish-*`.

Плашка создаётся как WPF-окно `Topmost` без панели задач. После создания HWND применяются `WS_EX_NOACTIVATE` и `WS_EX_TOOLWINDOW`, чтобы плашка не забирала фокус у активного окна.

Явный список прав доступа для именованного канала в первом этапе не задан. Это утилита координации, а не механизм безопасности или разграничения прав.
